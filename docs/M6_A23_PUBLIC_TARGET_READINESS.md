## Acceptance matrix

For every control, record `PASS`, `FAIL`, or `UNVERIFIED`. A release gate passes only with dated evidence for the named target and pinned revisions, generated by an appropriate technical method, independently reviewable, with no unresolved failure. Missing, stale, synthetic-only, or assertion-only evidence is `UNVERIFIED`. Any `FAIL` or `UNVERIFIED` blocks public acceptance. Do not place credentials, tokens, private keys, personal data, or secret values in evidence.

## Evidence format and offline validator

The minimal JSON format is versioned at `docs/public-target-evidence.schema.json`; a deliberately incomplete example is `docs/public-target-evidence.example.json`. Copy the example for a real target and preserve its `UNVERIFIED` entries until acceptable evidence exists. A complete package contains exactly 13 distinct, known control IDs; duplicate, missing, unknown, and excess controls are rejected. Status, target kind, method, and fields are allow-listed. PASS claims require a meaningful normalized production target ID, a valid RFC 3339 timestamp with explicit timezone and real calendar date, a named normalized reviewer, and meaningful evidence references. They must use `target_kind: "production"` and a technical method (`automated_probe`, `configuration_inspection`, or `independent_review`). `operator_assertion` and `synthetic_fixture` can never establish PASS. Incomplete `UNVERIFIED` packages may use `UNASSIGNED`, `NOT_CAPTURED`, and an empty evidence-reference list; these placeholders cannot support PASS.

Run `npm run validate:public-target-evidence -- path/to/evidence.json` for offline validation. It performs no network requests and validates structure and whether PASS claims meet the minimum claim-quality rules. `VALID` means only that the document is structurally acceptable; it does not authenticate references, signatures, reviewer identity, evidence truth or freshness, target state, or owner decisions. A well-formed PASS is still an unverified assertion until independent review of its referenced evidence. Secrets are not evidence fields; secret-like keys and values are rejected. Store only redacted references, never secret material.
