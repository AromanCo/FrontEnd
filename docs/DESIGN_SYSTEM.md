# AROMAN design system

Persian and RTL are defaults at the document root. The self-hosted variable Vazirmatn Arabic subset is loaded with `font-display: swap`; Arial is fallback. Core colors are ivory `#F7F2EC`, plum `#382A3D`, dark plum `#302434`, champagne `#D6AD72`, blush `#F2D5CF`, lilac `#C8AECF`, and sage `#93A58A`. Warm editorial surfaces, restrained borders, generous whitespace, and clear actions establish a living-atelier feel; lilac, blush, and botanical green are accents rather than a repeated purple wash.

`src/app/globals.css` contains the shared tokens and responsive layouts. The homepage uses a local SVG botanical/vessel illustration and sensory family color fields. Product tiles use replaceable concept artwork and label it as such; product photographs are not implied. The text AROMAN wordmark is a brand presentation, not an official logo asset.

The Creative Studio uses three reusable areas: `NoteLibrary`, `CompositionWorkspace`, and `ConceptPreview`. Note controls are buttons with soft-faceted clipped silhouettes, visible focus rings, selected/disabled states, family labels from the API, and a six-note limit. At 320px and 390px the library remains a two-column grid with readable names and no fixed sticky action bar. Mobile tabs expose Notes, Composition, and Result as distinct panels; desktop keeps the three areas visible together. Loading, API error/retry, valid empty result, and empty composition states retain their own layouts.

`FragranceVessel` is a lightweight local SVG concept illustration. Its ambient color is mapped from actual backend family labels by `familyMood`; layer distribution controls visual bands. This is presentation-only mood, not a claim about a physical formula or scent performance. SVG movement is restrained and disabled for reduced-motion preferences. No third-party photographs or remote image hosts are used.

The reviewed Stage 2 screenshots are in `design-references/figma-stage2/screenshots/`; the M1-B.2 decisions and known gaps are recorded in `docs/M1B2_HANDOFF.md`. Those images are design references rather than production assets. The local screenshot set is captured by `npm run screenshots:visual` into `artifacts/visual-alignment/`, preserving the earlier `artifacts/screenshots/` baseline.
