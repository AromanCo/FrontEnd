# M6-A28H — Lock Acceptance Matrix

## Status

All entries below are proposed future acceptance criteria, not completed checks. Dependency versions, hashes, lock identity, package provenance, and CI equivalence are currently `NOT_CAPTURED` or `UNVERIFIED`. Approval remains with the existing owner and release gates.

| ID | Acceptance requirement | Proposed verification | Failure behavior | Evidence / gate |
|---|---|---|---|---|

| LCK-02 | Exact Python patch, OS, architecture, ABI, pip, pip-tools and build toolchain are declared for each supported target. | Compare runtime fingerprints to target metadata in CI and image build. | Unsupported or mismatched target fails before installation. | Toolchain and platform evidence. |

## Acceptance boundary

Passing these tests would support a future owner-reviewed dependency-lock decision; it would not itself authorize production. Actual package resolution, hashes, target support, API compatibility, migrations, image identity, provenance trust, target controls, independent release review, and owner authorization remain subject to the existing release process. Production remains `NO-GO`; all 13 target controls remain `UNVERIFIED`; D1–D12 remain `OPEN`.
