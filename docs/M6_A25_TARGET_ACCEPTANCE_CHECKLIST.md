# M6-A25 Target Acceptance Checklist

Use only after the target architecture and audience have been separately selected and approved. This is provider-neutral preparation; it performs no probes and configures nothing. Retain redacted evidence in the approved controlled store. Exactly the 13 M6-A23 evidence controls apply. `PASS` requires appropriate production evidence and independent review; a repository check, fixture, assertion, or structurally valid JSON is not target evidence.

## Gate disposition

The offline gate reports separately: local code readiness, candidate integrity, decision completion, target acceptance, independent review, and owner approval. Missing any required item is **NO-GO**. Target evidence may remain `UNVERIFIED`; it is never promoted automatically. A complete local candidate can be reviewed but is not production approval. Signatures and authority must be verified through the separately approved human process, not by this validator.

## Safe probe boundary

This milestone includes offline planning and deterministic contract checks only. Any future live probe requires a separately authorized, exact target and explicit execution instruction. Limit probes to the approved hostnames, routes, methods, peer locations, rate and time window. Do not follow redirects to another origin. Stop immediately on scope ambiguity, unexpected exposure, sensitive response data, rate limiting, or any probe beyond authorization; retain redacted findings and notify the assigned owner through the approved process.
