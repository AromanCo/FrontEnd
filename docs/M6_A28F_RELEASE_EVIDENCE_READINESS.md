# M6-A28F — Release Evidence Readiness Register

## Purpose and rules

This register connects M6-A28B through M6-A28E evidence requirements to current repository records and the existing release gate. It creates no evidence or approval. `NOT_CAPTURED` means no evidence value is supplied; `UNVERIFIED` means repository structure or a claim exists without accepted target/authentication evidence; `MISSING` marks an absent prerequisite; `OWNER_DECISION_REQUIRED` marks an unresolved authority decision. Roles are not named where no accountable role is established. Do not promote synthetic evidence to a production release record.

The register maps to `docs/private-preproduction-release-record.example.json`, `docs/offline-artifact-manifest.example.json`, the M6-A28C manifest contract, M6-A28E provenance descriptors and the unchanged M6-A25/M6-A23 release decision gates. Existing safety values remain `deployable: false`, `production_acceptance_claim: false`, `public_release_disposition: NO-GO`; all 13 target controls remain `UNVERIFIED`; D1–D12 remain `OPEN`.

## Readiness summary

No production release evidence is generated by this register. Backend dependency resolution remains unverified and lock evidence remains missing. Builder/trust-root decisions, actual OCI identities, production Compose, schema/grants, content rights, target topology, capacity, recovery, monitoring, independent review and owner authorization remain absent or unverified. CI, static validation, synthetic examples and repository hashes cannot substitute for target evidence, approved lock verification, authenticated provenance, or the existing release gate.
